# PX-02 Executive Summary

## What should Atlas learn from the market?

Every construction SaaS product studied here — RDash, Powerplay, Buildertrend, Procore, Raken — solves the same underlying problem in the same underlying way: reduce how many places a person has to look, and reduce how many times the same information has to be re-entered or re-explained. Atlas has already built the *data* to do this — a single, real event ledger, a unified Commercial Engine, a deterministic reasoning layer (the CRE) — but has consistently under-invested in *composition*: turning data Atlas already has into the one artifact a real person actually wants each morning. Powerplay's own sub-60-second capture confirms Atlas's own Capture screen is already competitive. Raken's own daily-report discipline is the clearest, most direct opportunity Atlas hasn't yet taken. Buildertrend's own client-portal transparency is something Atlas already substantially has, quietly, without marketing it as such.

## What should Atlas deliberately avoid?

Procurement depth. RDash's own procurement-and-finance module is real and valuable to its own customers, but every layer of it (Material Requests → RFQs → Purchase Orders → GRN → Vendor Analytics) depends on the layer before it, and none of them extend naturally from Atlas's own current data model. Building even the first layer well would pull real engineering time away from the thing Atlas is already better at than any competitor reviewed here: deterministic, evidence-backed reasoning over real operational data. This sprint's own Section 7 recommends exactly one procurement-adjacent build in the next six months — applying the retention percentage Atlas already stores to real payment calculations — and explicitly classifies everything else as Later or Ignore.

## What is the single biggest UX change that would improve pilot adoption?

Promoting Inbox to a top-level navigation tab. This is the smallest engineering change in this entire roadmap (Phase A, 2-3 days) and the most frequently-hit friction point in daily use — clarifications, assignments, and payment updates all currently require a Profile detour to reach. Every other named scenario in this sprint's own Click-Count Analysis (Section 8) is already optimized by prior packages in this engagement (IN-01's deep-linking, UX-01's Capture design); Inbox promotion is the one remaining, genuinely available win.

## What is the single biggest operational capability Atlas should build next?

The AI Daily Site Report (Section 5). Every competitor reviewed here treats daily field reporting as core, and Atlas already captures every input such a report needs — voice, photo, GPS-tagged events, operational items, blockers, health signals — but has never composed them into one distributable artifact. Building this closes the single clearest gap against the market while playing directly to Atlas's own real differentiator: the report's own Forecast Impact section, powered by the CRE's existing deterministic reasoning, is something no competitor reviewed in this sprint combines with field reporting today. This is composition of existing intelligence, not a new engine — the lowest-risk, highest-differentiation build available to Atlas right now.
